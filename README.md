# linux-learn

请基于当前 Git Repo 中已有的需求文档，设计并实现一个轻量级、可交互的 HTML Requirement Explorer，帮助开发人员快速理解需求。

### 目标
减少阅读长篇 Markdown 的时间，让使用者先了解需求全貌，再按需查看字段映射、业务规则和待确认事项。

### 第一步：分析现有资料
1. 检查现有需求文档及相关目录。
2. 识别已确认需求、业务规则、字段映射、待确认问题和原始证据。
3. 找出重复内容及尚未确认的推断。
4. 先提出页面结构和数据来源方案，等待我确认后再修改文件。

### 第二步：实现页面
- 使用简洁的企业级界面，支持桌面端和移动端。
- 提供需求概览、数据流程、字段映射、业务规则、待确认事项等导航。
- 支持字段搜索、状态筛选和规则详情展开。
- 清晰区分已确认、待验证和待业务确认的信息。
- 重要规则显示来源文件或章节，方便追溯。
- 只展示简洁摘要，详细信息按需展开。
- 支持直接在浏览器中打开，不要求部署服务器。

### 第三步：实现约束
- 优先复用 Repo 中已有的需求文档和结构化数据，不重复手工维护同一份业务信息。
- HTML 应作为展示层，不应成为唯一的业务需求来源。
- 不得自行补充业务规则或将样例推断标记为已确认事实。
- 未经确认，不删除或重写现有需求文档。
- 尽量使用简单、可维护的技术方案，避免不必要的依赖。
- 如果需要 JavaScript，保持功能模块清晰，并处理缺失数据和无结果搜索。

### 第四步：验收
完成后说明如何打开页面，检查导航、搜索、筛选、详情展开及来源链接是否正常。
列出新增和修改的文件，并检查 HTML 内容与原始需求资料是否一致。

请先分析现有资料并提交实现计划，不要立即修改文件。
